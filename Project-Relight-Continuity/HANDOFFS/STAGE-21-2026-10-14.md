# Relight — Stage 21: hospedaje inicial del dashboard editorial

Fecha de implementación: 2026-10-14 · Zona America/Mexico_City.

## Objetivo y alcance autorizado

Habilitar la consola editorial en **https://kgblaze.dpdns.org/departures/dashboard/**,
con alias **/dashboard**, usando el mismo Worker, base D1 y biblioteca
publicada en Departures. No crear base paralela ni romper la consola
local V.25. El usuario pidió posponer configurar un sistema nuevo de
acceso; el requisito de seguridad no autoriza habilitar **publicaciones
anónimas**. La interfaz se puede abrir sin login adicional, pero
**guardar exige el ADMIN_TOKEN existente en memoria de la pestaña**.

## Primera versión web, no copia del operativo privado

La V.25 completa permanece deliberadamente fuera de GitHub,
Workers Assets y HTML público. La Library sólo contiene referencias
privadas a variantes históricas, no una versión V.25 autorizada para
publicación completa. Por ello se implementó un **panel web inicial**
en `src/dashboard-page.mjs`, con CSS y JS propios, sin fuentes
privadas, tokens, reservas ICS ni respaldos personales incrustados.

Implementa:
- Consulta real de `/departures/api/public`, misma agenda D1.
- Listado y filtros por nombre/categoría/fecha; edición de título,
  horario CDMX, día, categoría, estado, descripción, plataformas,
  ID de video YouTube y selección editorial de imagen.
- Creación/eliminación de eventos manuales.
- Biblioteca **`libraryCustom` compartida**: subir imagen PNG/JPG/WebP
  de hasta 1 MiB, nombre y alias; editar `libraryChanges` por JSON
  validado. No modificar prioridad de carátulas en ficha desplegable.
- Autopublicación al terminar cada cambio de campo con
  `POST /departures/api/admin/publish`, revisión CAS del backend,
  protección 423 de finalizados y protección 409 ante edición
  concurrente. Si falla, se bloquea la repetición y se puede exportar
  el borrador antes de recargar.
- Después de publicar, refresca el iframe de vista pública en la
  misma pestaña; dashboard consulta D1 cada 30 segundos cuando
  no hay cambios pendientes; el visor principal mantiene su propio
  polling histórico (unos 90 segundos) y recibe la revisión sin
  republicación manual.
- No escribe nunca observaciones verificadas YouTube/Twitch ni
  `sync_json`. La sincronización automatizada de Stage 20 queda
  independiente.

**No implementado aún en esta fase:** importación/editado ICS completo,
exportación del calendario 1080×1080, GIF HQ, edición avanzada de
imágenes ni todos los controles originales de V.25. El operativo local
permanece como respaldo y consola completa; no cambiar sus originales.

## Autenticación y seguridad preservada

El servidor no acepta POST anónimo aunque se publique el HTML. Se
reutiliza la verificación por hash del Bearer `ADMIN_TOKEN` y
`publishReconcile` del Worker. En el dominio personalizado sólo se
habilitan estas rutas prefijadas y con método validado:
`GET /departures/api/admin/snapshot`,
`GET /departures/api/admin/sync`,
`POST /departures/api/admin/publish`,
`POST /departures/api/admin/preview`.
Las rutas `/api/admin/*` no prefijadas, las demás API admin y otros
POST siguen sin acceso. La página se entrega con `no-store`,
`noindex`, CSP, `frame-ancestors none` y sin cargas JS externas.
El token no se incluye en el repositorio, URLs, localStorage ni
persistencia de navegador; sólo se utiliza al publicar.

**Prohibido** suprimir el Bearer o incrustarlo dentro del dashboard
para eliminar el campo de clave: ello abriría escritura de D1 a todos
los usuarios anónimos.
